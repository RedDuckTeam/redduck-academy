> We love a magic fix. A new tool, a new rule, a new process that will finally make the problem go away. Some of them help. But a tool only helps someone who already wants the result. It cannot hand you the wanting. When the wanting is missing, the tool just gets worked around, and you are left with the same problem wearing a badge that says solved.

## A tool measures the easy thing

Give someone a tool that checks their work, and look at what it actually checks. A common one for code checks spacing, commas, and naming. Useful, in its place. It also has nothing to say about whether the code is well built, which is the thing that actually matters.

So here is what happens. Someone leans on the tool, sees it turn green, and calls the work done, while the code underneath is fragile and falls over the first time anything unusual happens. The tool measured the easy thing, spacing, and stayed silent on the hard thing, design. Green is not the same as good. It only means the surface passed.

## A rule you resent, you will get around

A team once decided to force itself into better habits with a naming rule. Every saved change had to be labeled by type: a fix, a feature, a chore. The hope was that the rule would make them write clear labels.

It did not take long. Soon the labels read "chore: done", "fix: bugs", "chore: save". The team disliked writing clear labels so much that they added a rule to force themselves, then spent their energy slipping past it. A rule cannot make you want the thing. If the want is missing, the rule just becomes one more thing to dodge.

## The important thing hides behind the shiny one

There is a second trap here. A shiny optional improvement is exciting, so it pulls attention away from the dull, important thing that holds everything up. The same person proud of their new tool can be ignoring a real weakness sitting right next to it.

So when something promises to make a whole class of problems disappear, slow down. Ask what it actually checks, and whether the important thing is still getting your attention or only the shiny one.

## Start with the intent

A tool or a rule multiplies effort that already points the right way. It cannot point the effort for you. Before you add one, ask whether the real issue is that nobody has decided to do the thing well. If that is it, no tool will fix it, and adding one just hides the problem. Decide first. Then bring in the tool to help you do what you already meant to do.
